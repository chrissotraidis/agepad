# Steam engine on iPad: goal loop

**Objective.** Chris's existing Steam copy of AoE II: DE starts and plays on the iPad without his Mac at play time, by running Valve's genuine Steam client engine (the arm64 `steamclient.dylib` from his own Mac Steam install) inside AgePad. No new license. No faked Steam or ownership answers, no ownership bypass, no stub backend. The Mac's Steam sign-in, config and saves are never copied or modified; the engine uses its own Steam folder. Chris signs in himself (QR code with the Steam mobile app preferred, so AgePad never sees a password). Existing routes stay as fallbacks: Mac helper over Wi-Fi/Tailscale and the USB cable.

## Gates

| Gate | Pass | Status |

| 0b | Sign-in: QR code approved in the Steam mobile app (password + Steam Guard as fallback); remembered after restart | **Waiting for Chris's scan.** QR session via Steam's public IAuthenticationService works (`https://s.team/q/…` challenge, Steam-client token audience); `scripts/steam-engine-mac-test.sh signin` shows a self-refreshing QR page |
| 0c | Unmodified Mac DE reaches its menu against the headless engine, with an isolated home folder | Open |
| 0d | Wi-Fi off: engine offline mode, DE starts and plays a skirmish | Open |
| 1a–1f | Same on the iPad inside AgePad: sign-in screen, menu under 60 s with no Mac, airplane skirmish/save/resume, real online match, 60-min session under the 8 GB limit with in-match frame rate | Open |

**Stop rule.** If 0b cannot sign in without Steam's web window, stop this route, report, and fall back to the Mac helper with read caching and parallel prefetch.

## Evidence so far (26 Sep)

- **Main menu on the iPad through the in-app Steam (26 Sep, 11:40), no Mac.** Signed in as Chris (Aerophilian), build 25464371 (`docs/images/device-engine-menu-20260926.png`). Steam reports `can_logon_offline=1` after the online sign-in. Launch time was 1.5–3 min; a startup profile showed the game's main loop spent it in 2.2 million `stat` calls (1.7 M misses, 0.8 M case retries, ~40–60 µs each on the iPad). `port/de/DeviceDataTree.h` now answers queries inside the read-only data tree from an in-memory index (misses without a system call, any spelling → the real name, metadata cached once; disabled if the game writes there). Result: ~55 k real `stat` calls, menu ≈60 s after an icon tap (intro videos ≈25 s of that). A game-to-engine Steam call costs ~43 µs (Mac measurement), so Steam is not the bottleneck. The game recognises the `SKIPINTRO` launch option; applying it to icon launches is next (not yet verified — the test run's screen was off).
- **iPad with Chris's account (26 Sep, 10:58–11:23).** QR sign-in approved on Chris's phone; token saved to the iPad Keychain. Findings in order: (1) iPadOS kills the app on System V `semget` (Valve's `libtier0` named locks) → in-process semaphore sets in `port/de/SysVSemaphoreCompat.h` (via `IPCSystemCompat`). (2) Launched like an icon tap, the saved sign-in logs on with no Mac (`Using JWT … expiry Apr 2027`, `'OK'`). (3) The game attached too early (`connect to global user failed`) → AgePad now waits for Steam's own `BIsSubscribedApp(813780)` (true). (4) Then the game's `SteamInitialization::HandleStatusFailure` showed "A running process may be interfering…": the in-app Steam had no install record (`Loaded 0 apps`) → the build now bakes the Mac's appmanifest for build 25464371 (the verified-identical import), personal fields dropped, auto-update "on launch only", separate empty install folder. (5) With that, no warning; the game ran 3 minutes at 120 fps, footprint 3.4 GB, main thread alive, until Chris switched apps. Menu not yet seen on screen.
- **iPad, engine inside AgePad (build installed 26 Sep ~10:50).** The app's default route now starts Valve's engine in-process (`port/steam-engine/SteamEngineHost.c`, methods found at run time by the name each proxy method passes to its IPC call, so Steam updates don't break the slot map; verified against both the packaged and the current Mac Steam builds). Setup screen: QR sign-in (`AgePadSteamRoute.m`), with "Play with my Mac's Steam instead" when paired; USB `play` still uses the Mac automatically. The engine hit Mac-only calls; each now gets a real iPad answer in `DEClientBoundary_*` replacements built by `build-de-device-runtime.py`: DiskArbitration unavailable (Valve's caller checks for NULL), input-idle/front-process = AgePad is the active app (`CSteamEngine::CheckForComputerUse`), one display sized from the real screen. Evidence: anonymous Steam logon from the iPad engine reached `logged_on=1` in ~2 s. With `AGEPAD_ENGINE_ANON_GAME=1` the whole plumbing ran: engine logged on → registered with the in-app `ipcserver` (op 13) → game's own `SteamAPI_Init` read it back (op 14) and loaded the in-app `steamclient.dylib` → Steam reported no licensed user (`CreateFn failed for SteamUser021`) and the game exited itself cleanly. That is the genuine answer for an anonymous session; the real test needs Chris's QR sign-in.
- **Engine interface map.** `IClientUser` methods were labelled from each IPC proxy method's own name string (`generated/steam-engine/user-slot-names.txt`): LogOn(CSteamID)=1, LogOff=3, BLoggedOn=4, GetLogonState=5, BConnected=6, GetSteamID=10, SetLoginToken(token, account)=56, CanLogonOffline=214, LogOnOffline(bool)=215. (The name-table order is not the vtable order; an early probe called LogOff by mistake.)
- **How a game finds Steam.** `libsteam_api` asks Valve's `ipcserver` (launchd service `com.valvesoftware.steam.ipctool`) for Steam's pid and executable path (operation 14), then loads `steamclient.dylib` from that folder and connects to the running engine. `steam_osx`, as Steam's launcher, registers itself with operation 13 {pid, path}. With Mac Steam quit, the probe registered itself the same way and DE's unmodified `libsteam_api` loaded the isolated engine and reached `connect to global user failed` — the real, expected answer while nobody is signed in. On the iPad, AgePad is the launcher: Valve's `ipcserver` already runs in-app (`AGEPAD_DEVICE_LOCAL_IPC_PROBE`), so the engine registers the same way.
- The game library also needs its app ID: `steam_appid.txt` (Valve's documented developer mechanism) or the launcher's environment.
- The Wi-Fi bottleneck is 34,121 sequential Steam round trips at startup (10,262 real calls at ~3 round trips each; 370 achievements and ~1,200 stats read repeatedly; 5,026 distinct calls). Measured with the helper's opt-in capture. An in-device engine makes these local.
- `steamclient.dylib` is native arm64 and contains the client engine; the Steam app (`steam_osx`) is a launcher and the visible UI is a separate web layer (`steamui.dylib`, `steamwebhelper`).
- The library carries ordered method-name tables for its internal interfaces (e.g. IClientUser: LogOn, LogOff, BLoggedOn, … BHasCachedCredentials, DestroyCachedCredentials, SetAccountNameForCachedCredentialLogin, SetLoginInformation, SetLoginToken …), so interfaces can be mapped by name.
- Modern sign-in is inside the engine: Authentication service calls GetPasswordRSAPublicKey, BeginAuthSessionViaCredentials, BeginAuthSessionViaQR, UpdateAuthSessionWithSteamGuardCode, PollAuthSessionStatus, reachable through IClientUnifiedMessages (SendMethod, GetMethodResponseInfo, GetMethodResponseData, ReleaseMethod) — the same path Steam's login window uses.
- It spawns programs in places (fork, posix_spawn, popen); iPadOS forbids this, so those paths must fail safely.
- The Mac's saved sign-in (config/local.vdf, ssfn sentry file) is machine-bound and is never copied.
- The game binary also contains Feral Store, StoreKit/Game Center and Epic backends; they are not used (no new license).
