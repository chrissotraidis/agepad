## Iteration 298: real Metal BC4 upload/decode operation passes Simulator pixels

Previous turn classified as progress. This turn implements a GPU-side BC4 UNORM decoder in port/de/BC4MetalDecode.m/h. It accepts a real Metal source buffer and writable R8 2D texture, validates source/destination bounds and device ownership, and encodes a compute pass without committing or waiting. The caller must finish the current encoder first. This is important for original uploads from GPU/private buffers: CPU .contents decoding cannot safely read those or preserve ordering. The decoder processes one compressed block per compute thread, crops edge blocks, respects byte pitch and source offset, and writes only the specified destination region. Source offsets currently require four-byte alignment. It supports level0 2D R8 targets only; no BC1/2/3/5/6/7, signed, sRGB, array, or mip-view integration is claimed. R8 output has up to one integer unit of quantization tolerance against the independent interpolation formula; this is not bit-exact float sampling equivalence.

## Simulator-specific constraint verified now

Actual generated/mac-de-rendering-review/simulator-features.json: Apple iOS simulator GPU; supports Apple families1/2 only; Mac2=false; argumentBuffersSupport raw0 (Tier1); readWriteTextureSupport raw0 (None); hasUnifiedMemory=false; maxBufferLength268435456 (256MiB). Its registryID matches the native Apple M2 GPU, but the native GPU reports unified memory. Do not replace capability answers to force the renderer past requirements: resource/pipeline execution must succeed on actual supported features.

Apple explicitly says [Simulator does not emulate the named iPad GPU](https://developer.apple.com/documentation/metal/developing-metal-apps-that-run-in-simulator). It can expose substantially fewer capabilities than actual Apple GPUs. Its restrictions include buffer alignment, texture storage/formats and programmable blending. Consequently a Simulator-only shader failure can be a limitation of this test environment rather than proof of physical-iPad impossibility. User preference remains Simulator first; no physical-device work is implied by this finding.
