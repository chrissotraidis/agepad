## Fixed in this pass

1. **Paste permission prompt on every launch.** The launcher WebView probes paste
   availability; our `NSPasteboard` bridge answered by reading `UIPasteboard.string`,
   which iOS gates behind a prompt. `PasteboardCompat.m` now answers availability
   from `hasStrings` and only reads contents within 2 s of a ⌘V key event. Verified:
   two subsequent launches showed no prompt.
2. **Crash on backgrounding.** On resign-active the game calls
   `CGGetOnlineDisplayList`; the CoreGraphics boundary had a fail-fast stub, so the
   process aborted (crash log `DEOriginalGame-2026-09-18-200629.ips`).
   `DisplayLifecycleCompat.m` now returns the UIKit screens with the identifiers the
   other display bridges use. `build-de-simulator-runtime.py` strips generated stubs
   for any symbol `port/de` implements, so the private package file stays pristine.

## Found, not fixed

- **Xbox Network sign-in does nothing.** The button hover/tooltip works and the
  click is dispatched, but no sign-in window appears and neither MainLog nor our
  runtime logs anything. XAL (`Xal_macOS`) presents Microsoft login through
  `XALWebKitController`: an NSWindow + NSViewController hosting a WKWebView. Our
  AppKit boundary never received a second window request, so the failure is
  earlier — probably the game gating sign-in on a condition we don't satisfy, or
  XAL's window-controller path failing silently. Only needed for Xbox-network
  multiplayer/co-op; local play and Steam identity are unaffected.
- **Two-finger pan and pinch** remain untested: the automation cannot hold a
  modifier through a drag, and Simulator two-finger input needs that. Real
  hardware required.
- **Home-screen icon is the placeholder grid.** Packaging polish.
- Sustained frame-time distribution still unmeasured; throughput this pass was
  21/s at host load 24–37.
