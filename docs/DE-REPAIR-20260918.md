# September 18 repair: failed touch orders were long right-button holds

## Root cause

The touch delivery layer (`port/de/OrderedMouseDelivery.h`) held every button
release until two later compositions had been observed, up to one second. That
guard was added so menu clicks would not be missed between polls. For the
secondary button it turned a tap into a long hold whenever rendering was slow.
DE treats a held right button as the start of click-drag scrolling, so the
release produced no command.

Every run with release-gate data showed the same split:

| Run | Failed orders (held ms) | Accepted orders (held ms) |
| --- | --- | --- |
| keyboard-sampler-normal-20260914 | 684, 1001, 630, 403 | 104, 137, 133 |
| play-loop-reload-20260914 | — | 120, 100, 101 |
| hardware-secondary / keyboard-command / resource-* 20260914 | 1000–1001 (timeout, 0 frames) | — |
| promotion-20260915 | 551, 318 | — |

No accepted order held longer than 137 ms; no failed order held shorter than
318 ms. The September 14 note attributing success to the Click-Drag Scrolling
option was a coincidence: host load dropped at the same time, compositions
sped up, and the holds shortened. That note is superseded.

## Fix

`DE_SECONDARY_MAX_HOLD` (160 ms) bounds the secondary release. The 100 ms
minimum press is kept; the composition wait still applies to the primary
button. When the cap expires with zero observed frames the release is sent
anyway. Change is confined to `OrderedMouseDelivery.h`; the actual-adapter
regression `tests/test_de_touch_ordering.py` passes.

## Live result (fresh launch, AGEPADPLAY914, no Options visit)

- 20 consecutive ORDER + ground taps. All 20 released within 100–161 ms
  (one hit the cap with 0 frames observed and was still accepted).
- 18 visually confirmed as accepted (mid-walk and arrival frames). 2 were
  scored unclear only because the next order was issued before the walk
  finished; neither showed a failure. Zero observed rejections.
- One tap on a tree was accepted as a gather order (villager became Lumberjack).
- Box selection by drag selected two villagers. This had been recorded as
  failing on September 12.
- 30-second throughput 21.0 compositions/s (interval 12.0–28.1) at host load
  24, sole designated Simulator throughout.

Evidence: `generated/secondary-hold-20260918/` and run
`generated/mac-de-simulator-375/secondary-hold-20260918b/`. Candidate
`generated/simulator-repair-20260918/secondary-hold-candidate`, installed into
the package `game-client` directory; previous AppKit boundary preserved as
`before-DEBoundary_AppKit.dylib`.

## Still open

Two-finger pan and pinch through `NativeTouchGestures.m` have not been
re-tested under this change; they send their own secondary/scroll events and
need real multi-touch hardware for acceptance. Sustained performance, device
packaging and the Steam service arrangement are unchanged; see
[AGEPAD-RECOVERY-PLAN-20260916.md](AGEPAD-RECOVERY-PLAN-20260916.md).
